Coin Garden · App Map

A take-home guide to where things live and how one action flows through the app.

What it is, in a few pieces

Coin Garden turns each crypto purchase into a seed that grows as the price rises toward x2. It has three kinds of code:

  • BrowserThe garden and notebook: React client components in components/, driven by two hooks in hooks/. Your plants are saved in this browser's localStorage.
  • ServerTwo API routes in app/api/. They ask CoinGecko for coin search and prices, with a shared cache of about a minute.
  • Pure logicSmall functions in lib/, such as stageFor(), which decides how grown every plant is. They are unit-tested.

One action: "I plant a coin and see how far it has grown"

Text version: the notebook form → useGarden.addPlant → saved to localStorage and prices requested from /api/prices → CoinGecko (cached) → stageFor(buy, current) → Plant draws the stage.

Reference route: three stops

This is a reference route to read on your own. It wasn't toured together live.

  1. Browsercomponents/notebook/NewEntryPage.tsx → search function submit

    This validates the four fields, then hands a NewPlant to onPlant. Above it, CoinGardenApp.tsx wires that to garden.addPlant.

  2. Browserhooks/useGarden.ts → search loadGarden() and const addPlant

    This is your server-vs-browser question in code. The saved garden is read inside useEffect, after the page mounts, because the server rendered the HTML without knowing what's in your localStorage. Every change is saved back, and the unique coin ids are sent to /api/prices.

  3. Serverapp/api/prices/route.ts → lib/coingecko.ts → search export async function fetchPrices

    The route runs on the server and calls the "use cache" helper. It asks CoinGecko once a minute at most, and the result is shared by every visitor. Then, back in the browser, lib/growth.ts → stageFor turns the price into a stage.

A practice to reuse

Put the core rule in one pure, tested function, and let everything else call it.

In this project, the kernel ("losses stay seeds, x2 is a sunflower") lives only in stageFor() in lib/growth.ts. The live garden, the 10-second Demo (lib/demo.ts) and the notebook guide page all call it. lib/growth.test.ts pins the exact thresholds (1.24 → seed, 1.25 → sprout, 2 → sunflower). lib/demo.test.ts proves the Demo passes through every stage in order, because it uses the same function.

On your next project, ask early: what is the one rule that makes this product itself? Give it a single home with no React, storage or network inside, and test it first. Then the UI, the API and any "demo mode" are just different ways of feeding it inputs.
